
# Fast Wiki轻量级文档渲染系统指南

预览地址：https://cli.cc/wiki/

## 1. 系统概述与核心理念

本系统是一款基于「纯运行时驱动」的轻量级文档渲染引擎。其核心设计理念旨在结合 **Docsify 的零构建优势**与 **Vitepress 的现代化 UI/UX 体验**，并通过轻量级的后端（PHP）介入，彻底解决纯前端架构在文件系统读取、索引构建和路由管理上的先天性工程缺陷。

### 1.1 核心技术特征
* **快速部署**： 采用传统前端开发和php脚本，只需要将md文件丢入docs文件夹中就可以自动生成文档。php接口也可以用其它语言实现，不一定非得用php，超级解耦，超级快捷。  
* **零编译/零构建**：完全抛弃 Node.js、Webpack、Vite 等构建工具链。文档修改即刻生效，部署仅需极基础的 Web 容器。
* **混合架构模式**：采用 PHP 处理文件系统的 I/O 遍历与结构序列化，采用纯前端（Vanilla JS + Fetch API）处理路由拦截、Markdown 动态解析与 DOM 渲染。
* **物理路径解耦**：独创的 `标题[路由][排序]` 命名规范，将物理文件系统与前端逻辑路由彻底解耦，提供极高的菜单定制自由度。
* **高性能本地检索**：摒弃前端纯爬虫式的并发请求灾难，采用后端一次性聚合索引 + 前端 Fuse.js 模糊匹配方案，兼顾网络性能与检索精度。

## 2. 目录结构规范

要熟练使用本系统，首先需要理解系统底层的目录映射关系。系统的标准拓扑结构如下：

```text
/项目根目录
│  index.html            # 前端入口视图文件（单页应用核心）
│
├─api/                   # 后端接口核心组件
│      sidebar.php       # 负责扫描 docs 目录并生成菜单层级结构与物理映射表
│      search.php        # 负责递归读取所有文档内容，构建全文检索引擎的 JSON 词库
│
├─assets/                # 静态资源中心
│      main.css          # 全局样式表（包含 CSS Variables 主题定义与响应式逻辑）
│      main.js           # 前端核心引擎（负责路由监听、Fetch 数据流、DOM 操作）
│
└─docs/                  # 【核心工作区】所有 Markdown 文档存放在此
       _全局配置说明.md     # 以下划线开头的文档将被系统忽略，不参与渲染
       系统简介[intro][0].md
       ...

```

## 3. 普通用户指南：如何编写与管理文档

对于内容创作者和普通用户而言，本系统的核心操作全部集中在 `docs` 目录下的文件管理与命名上。系统不需要你编写任何 `json` 或 `yaml` 配置文件，**“文件系统的物理拓扑即是网站的导航拓扑”**。

### 3.1 核心命名规范：`标题[路由][排序]`

为了在不需要配置文件的前提下实现复杂的菜单命名、URL 美化以及自定义排序，本系统引入了一套基于文件名的正则提取规则。

无论是一个 **`.md` 文件** 还是一个 **文件夹（目录）**，均严格遵循以下命名公式（参数均为可选）：

> **公式：`显示名称[英文路由][排序数字]**`

#### 规则解析与最佳实践：

1. **显示名称（必填）**：不包含中括号的部分。这将直接作为左侧菜单栏和浏览器 Title 显示的名字。
2. **`[英文路由]`（可选）**：由于中文 URL 路径在某些老旧浏览器或分享时会被 URL Encode 成为长串乱码，你可以通过第一个中括号指定一个简短的英文别名作为 Hash 路由。
* *如果没有提供此项，系统会自动回退使用「显示名称」作为路由。*


3. **`[排序数字]`（可选）**：用于干预目录和文档的上下排列顺序。**数字越小，排名越靠前**。
* *如果没有提供此项，系统将自动读取文件的「最后修改时间（时间戳）」。由于时间戳数值极大（通常为十几亿），因此所有手工指定了排序编号（如 `[0]`, `[1]`）的文件/文件夹，永远会绝对置顶于未指定排序的常规文件之上。在未指定排序的文件组内部，越老的文件越靠前（自然排序）。*



#### 命名范例大全：

* **常规命名**：`安装说明.md`
* 菜单显示：安装说明
* URL 访问路径：`#/安装说明`
* 排序权重：文件修改时间戳（靠后）


* **指定路由**：`核心原理[core-concept].md`
* 菜单显示：核心原理
* URL 访问路径：`#/core-concept`（URL 更加美观专业）
* 排序权重：文件修改时间戳（靠后）


* **指定路由与排序**：`快速开始[quick-start][1].md`
* 菜单显示：快速开始
* URL 访问路径：`#/quick-start`
* 排序权重：`1`（极高优先级，排在最前面）


* **仅指定排序，跳过路由**：`常见问题[][99].md`
* 菜单显示：常见问题
* URL 访问路径：`#/常见问题`
* 排序权重：`99`



### 3.2 多级菜单（二级、三级树状结构）的生成

本系统支持无限层级的递归菜单生成。你只需要在 `docs` 目录下建立文件夹即可。

**文件夹的命名规则与文件完全一致！**

**实战场景**：我们需要一个包含基础教程和高级进阶的文档树。

你可以这样建立目录结构：

```text
docs/
 ├─ 01_欢迎使用[home][0].md
 │
 ├─ 基础教程[basic][1]/          <-- 文件夹名称
 │   ├─ 环境准备[env][0].md
 │   └─ 第一行代码[hello][1].md
 │
 └─ 高级进阶[advanced][2]/       <-- 文件夹名称
     ├─ 内存管理[memory][0].md
     └─ 性能优化[performance][1].md

```

系统后端在扫描到上述结构时，会自动将其序列化。前端渲染时，会生成如下逻辑：

1. 左侧会出现两个可以一键展开/折叠的父级菜单：「基础教程」和「高级进阶」。
2. 当点击「内存管理」时，浏览器的 URL 将变更为：`#/advanced/memory`。系统会通过内存中的哈希映射表，精准反查出应该去请求 `docs/高级进阶[advanced][2]/内存管理[memory][0].md` 这个物理实体文件。

### 3.3 隐藏文件与辅助说明文档

在文档编写过程中，你可能需要撰写一些不对外公开的草稿、协作说明或附件（如 `README.md`、`_素材记录.md`）。

* **忽略规则**：只要文件名以点 `.` 或下划线 `_` 开头，后端的扫描引擎就会将其直接过滤。它既不会出现在左侧菜单中，也不会被编入全文检索引擎。

### 3.4 Markdown 语法与视觉排版支持

本系统接入了 `markdown-it` 引擎，并配合 Vitepress 风格的 CSS 变量，为你提供企业级的排版体验：

* **页面大纲 (TOC)**：你无需在文档内手动编写 `[TOC]`。系统会自动提取当前文档内所有的 `H2 (##)` 和 `H3 (###)` 标题，并在页面右侧悬浮生成随内容滚动而高亮的文章大纲。
* **代码高亮**：原生集成了 `Prism.js`。只需在代码块反引号后指定语言标识符（如 `php`, `javascript`, `go`, `python`, `json`, `bash` 等），即可呈现出极其精准的深色风格高亮。
* **数学公式**：原生集成了全球最快的公式渲染器 `KaTeX`。你可以自由书写复杂公式。
* **自定义容器块**：通过原生的 Blockquote 样式重写，支持类似 Vitepress 的高亮提示框（通过 HTML 注入或自定义 CSS 类可扩展出 `tip`, `warning`, `danger` 等块级元素）。

### 3.5 用户界面交互体验 (UI/UX)

* **响应式侧边栏**：PC 端支持鼠标拖拽侧边栏右侧边缘动态调节宽度。如果觉得左侧菜单阻碍了沉浸式阅读，可点击底部的“收起”按钮将其隐藏，左下角会悬浮唤出恢复按钮。
* **移动端终极适配**：当屏幕宽度缩小到 768px 以下时，系统会自动重组 UI。左侧菜单将转变为隐藏式抽屉（Drawer），右侧大纲强制隐藏，顶部导航栏出现汉堡菜单按钮（Hamburger Button），最大化释放移动设备的横向阅读空间。
* **全文即时检索**：按下 `Ctrl + K` 或点击顶部搜索栏唤出。系统会使用本地 `Fuse.js` 引擎对后台聚合好的 JSON 语料库进行模糊匹配，即使文档字数较多，检索延迟也严格控制在毫秒级，并支持关键词截取与着色高亮。

## 4. 开发者指南：系统架构解析与二次开发

对于全栈开发人员，本系统在工程结构上做了极致的解耦，代码完全处于白盒状态，提供了巨大的二次开发和魔改空间。

### 4.1 技术栈概览与架构原理

* **数据层 (Backend)**：PHP 8+ 脚本。规避了纯前端模式必须通过暴力发起大量 Fetch 嗅探目录的性能瓶颈。利用 PHP 的本地文件系统操作权限，将树状结构和文件内容序列化为 JSON API。
* **网络层 (Transport)**：浏览器 Fetch API 处理数据流交互，基于 DOM `hashchange` 事件驱动 SPA（单页应用）路由。
* **展示层 (Frontend)**：Vanilla JS（原生无框架 JS）+ CSS Variables。
* **解析引擎**：`markdown-it` (核心转换)、`Prism.js` (词法高亮)、`Fuse.js` (模糊检索引擎)。

#### 核心状态管理：物理路径映射表 (`window.routeMap`)

由于我们将“物理文件名称”与“前端美化路由”进行了拆分，在 `assets/main.js` 中维护了一个全局哈希表。
在 `initTree()` 阶段，前端获得来自 `sidebar.php` 的 JSON 数据后，会构建类似如下的映射：

```javascript
window.routeMap = {
    "home": "01_欢迎使用[home][0].md",
    "advanced/memory": "高级进阶[advanced][2]/内存管理[memory][0].md"
};

```

当 URL 产生变化 `#/advanced/memory` 时，引擎直接通过 $O(1)$ 时间复杂度从哈希表取得真实路径，拼接上 `docs/` 进行资源请求。这就彻底解决了复杂字符和多级目录下的 404 困境。

### 4.2 后端二次开发：API 层魔改

后端的两个 PHP 文件非常纯粹，均独立运行并返回 `application/json` 头。

#### 场景 1：修改命名解析正则 ( `api/sidebar.php` )

如果你觉得当前的 `标题[路由][排序]` 不够用，想加入例如 `[图标]`、`[权限标识]` 的属性，你可以修改正则表达式：

```php
// 原正则：preg_match('/^([^\[\]]+)(?:\[([^\[\]]+)\])?(?:\[(\d+)\])?$/', $filename,$matches)
// 扩展后：加入第四个提取维度
preg_match('/^([^\[\]]+)(?:\[([^\[\]]+)\])?(?:\[(\d+)\])?(?:\[(icon-[a-z]+)\])?$/', $filename,$matches)

```

修改后，你需要在返回的 `$result` 数组中增加 `icon` 字段，并在前端 `main.js` 的 `renderSidebar` 函数中拼接对应的 HTML 标签（如 FontAwesome 图标）。

#### 场景 2：搜索聚合的深度过滤 ( `api/search.php` )

如果你的文档库高达几万篇，目前的 `api/search.php` 会造成单次返回的 JSON 体积过大。针对大规模生产环境，你可以进行以下二次开发：

1. **加入 Redis 或本地文件缓存**：在每次文档更新时触发重新构建，平时只从缓存读取 JSON，大幅降低 PHP IO 开销。
2. **正文摘要算法优化**：不再仅仅利用 `strip_tags` 清理 HTML，可以通过更严谨的正则，将代码块 ```` ` 内部的代码从索引库中剔除，专注索引人类语言描述文本，从而将 JSON 语料库体积压缩 60% 以上。

### 4.3 前端二次开发：渲染引擎与 UI 魔改

#### 场景 1：引入新的代码高亮语言支持

当前系统默认引入了常见的后端与前端语种。如果你需要加入（例如） Rust 或 C++ 支持：

1. 打开 `index.html`，定位到底部引入 `Prism.js` 的区域。
2. **严格注意依赖顺序**：Prism 的组件加载对顺序要求极高。如 PHP 必须在 `markup-templating` 之后。
3. 通过 jsDelivr 追加所需的语种脚本：
`<script src="https://cdn.jsdelivr.net/npm/prismjs@1.29.0/components/prism-rust.min.js"></script>`

#### 场景 2：替换系统主题与配色模式

整个系统抛弃了传统的预处理语言（LESS/SASS），全部采用原生的 CSS Variables (`var(--vp-...)`) 挂载于 `:root` 选择器上。
你只需要打开 `assets/main.css` 顶部，修改 `VP (Vitepress)` 风格变量：

```css
:root {
    --vp-c-brand: #3451b2; /* 核心品牌色，可修改为你的企业蓝/科技绿 */
    --vp-c-brand-light: #3a5ccc;
    --vp-sidebar-width: 272px; /* 默认侧边栏宽度 */
}

```

并且系统原生支持基于系统偏好的深色模式适配（通过 `@media (prefers-color-scheme: dark)` 侦测），如果需要增加主动的深浅色切换按钮，可以在 JS 中拦截该事件，手动往 `document.body` 或 `html` 标签注入 `.dark` 类，并在 CSS 中将媒体查询改为类选择器匹配。

#### 场景 3：挂载 Markdown-it 扩展插件

为了实现类似 Vitepress 独有的块级结构：

```markdown
::: tip 提示
这是一段重要信息
:::

```

你可以在 `index.html` 中引入 `markdown-it-container` 插件：

1. 引入 CDN：`<script src="https://cdn.jsdelivr.net/npm/markdown-it-container/dist/markdown-it-container.min.js"></script>`
2. 在 `main.js` 的初始化引擎代码处，将其注册进 `md` 实例：
```javascript
md.use(window.markdownitContainer, 'tip', {
    render: function (tokens, idx) {
        var m = tokens[idx].info.trim().match(/^tip\s+(.*)$/);
        if (tokens[idx].nesting === 1) {
            return '<div class="custom-block tip"><p class="custom-block-title">' + md.utils.escapeHtml(m[1] || 'TIP') + '</p>\n';
        } else {
            return '</div>\n';
        }
    }
});

```



### 4.4 调试与排错指南

在进行二次开发或环境部署时，如遇故障可参考以下排查路径：

* **症状：点击某个菜单后，控制台抛出 fetch 错误，且右侧显示 `404 未找到文档路径`。**
* **根源分析**：通常发生于含有中文名的复杂文件。前端使用 `fetch` 向 HTTP Server 发起请求时，由于操作系统底层的编码差异或 Nginx 的 Rewrite 机制，未能正确解析中文。
* **排错动作**：检查 `main.js` 中 `fetchUrl` 的拼接逻辑。确保已使用 `encodeURIComponent` 对切割后的路径片段进行了严格的安全转义（系统目前已经集成了此修复方案）。


* **症状：页面白屏或代码块报错 `Cannot read properties of undefined (reading 'tokenizePlaceholders')**`。
* **根源分析**：`Prism.js` 依赖核心 `markup-templating` 缺失或加载顺序颠倒。
* **排错动作**：检查 `index.html` 中 `prism-markup-templating.min.js` 是否处于 `prism-php.min.js` 之前。若遇到国内网络污染导致 CDN 资源 404，需将其全部替换为更稳定的镜像或将 JS 库下载到本地。


* **症状：侧边栏的展开/收缩在移动端出现撕裂，或 PC 端状态无法恢复。**
* **根源分析**：移动端的隐藏抽屉（`transform: translateX(-100%)`）与 PC 端的强行折叠视图（添加 `.sidebar-collapsed` 类）产生了 CSS 优先级的冲突。
* **排错动作**：确保在 `window` 侦测尺寸变化的 `resize` 事件钩子中，严格执行对 `sidebar-collapsed` 的卸载操作，杜绝 PC 端状态残留在移动端视图中。系统默认已摒弃 `localStorage` 缓存状态，采用每次刷新还原为纯净态的策略保障渲染的一致性。
