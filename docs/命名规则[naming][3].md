# 命名规则

本系统不需要任何 `json` 或 `yaml` 配置文件，**文件系统的物理拓扑即是网站的导航拓扑**。无论是 `.md` 文件还是文件夹，都遵循同一套命名规范。

## 命名公式

```
显示名称[英文路由][排序数字]
```

三个参数均为可选，但顺序固定：先路由、后排序。

### 1. 显示名称（必填）

不包含中括号的部分，直接作为左侧菜单和浏览器标题显示。

### 2. 英文路由（可选）

第一个中括号，指定一个简短的英文别名作为 Hash 路由，避免中文被 URL Encode 成长串乱码。

> 未提供时，系统自动回退使用「显示名称」作为路由。

### 3. 排序数字（可选）

第二个中括号，控制菜单上下顺序。**数字越小越靠前**。

> 未提供时，系统读取文件「最后修改时间戳」作为权重。由于时间戳极大（十几亿），手工指定的编号（如 `[0]`、`[1]`）永远排在未指定的文件之上；未指定组内部按修改时间升序排列。

## 命名示例大全

| 文件名 | 菜单显示 | URL 路径 | 排序权重 |
|---|---|---|---|
| `安装说明.md` | 安装说明 | `#/安装说明` | 修改时间戳（靠后） |
| `核心原理[core-concept].md` | 核心原理 | `#/core-concept` | 修改时间戳（靠后） |
| `快速开始[quick-start][1].md` | 快速开始 | `#/quick-start` | `1`（极高） |
| `常见问题[][99].md` | 常见问题 | `#/常见问题` | `99` |

## 隐藏文件

文件名以 `.` 或 `_` 开头的文件会被后端扫描引擎直接过滤，既不出现在菜单中，也不被编入检索索引。适合存放草稿、协作说明、素材等。

示例：

```text
docs/
├─ _草稿.md            # 不参与渲染
├─ .素材记录.md         # 不参与渲染
└─ 正式文档[intro].md   # 正常渲染
```

## 多级菜单

在 `docs` 下建立文件夹即可生成多级菜单，**文件夹的命名规则与文件完全一致**。

```text
docs/
├─ 欢迎使用[home][0].md
├─ 基础教程[basic][1]/
│   ├─ 环境准备[env][0].md
│   └─ 第一行代码[hello][1].md
└─ 高级进阶[advanced][2]/
    ├─ 内存管理[memory][0].md
    └─ 性能优化[performance][1].md
```

渲染效果：

- 左侧出现两个可展开/折叠的父级菜单：「基础教程」「高级进阶」
- 点击「内存管理」时，URL 变为 `#/advanced/memory`
- 系统通过内存哈希表反查物理路径，请求 `docs/高级进阶[advanced][2]/内存管理[memory][0].md`

> 想看实际效果？本示例文档左侧菜单的「基础教程」「进阶示例」就是多级菜单的真实演示。

## 最佳实践

1. **统一用英文路由**：保持 URL 简洁、专业，便于分享与记忆。
2. **关键文档指定小排序号**：如 `[0]`、`[1]`、`[2]`，确保它们永远置顶。
3. **文件夹也指定路由与排序**：避免子目录的路由和顺序不可控。
4. **辅助文档用 `_` 前缀**：保持 `docs` 目录整洁。
