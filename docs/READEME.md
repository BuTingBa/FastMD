

# 恒温化学搅拌系统 (Smart Thermal-Stirring System)

基于 ESP32-C3 (ESP-IDF) 开发的智能恒温化学搅拌器。集成了高精度 PID 控温、PWM 电机搅拌、自动化散热、无级称重滤波以及无线 (ESP-NOW) 测温节点交互功能。搭配淘晶驰串口屏提供丝滑的本地 UI 监控与控制。**该项目原本基于ESP32-P4开发，但在开发过程中P4烧毁，无奈采用C3开发。如果风扇不转动，将插在 TB6612 AO1 和 AO2 上的两根风扇线互换位置**

## 🌟 1. 功能要点

* **无线测温矩阵 (ESP-NOW)**：摒弃易受腐蚀和缠绕的有线探头，采用独立的 C3+MAX31865 节点采集温度，通过无连接、低延迟的 ESP-NOW 协议投递真实温度，支持 MAC 地址绑定。
* **高精度 PID 控温**：基于实时温度、目标温度、比热容与质量的多维前馈 PID 算法，通过 SSR (固态继电器) 驱动加热元件，内置 0.0g 级硬件防干烧保护。
* **动态防抖称重 (HX711)**：采用工业级死区滤波 (Deadband) 与零点钳位 (Zero-clamping) 算法，屏蔽环境底噪与电机高频震动，确保 UI 显示稳如泰山。
* **异构电机驱动管理 (TB6612)**：
* **搅拌控制 (Motor B)**：软件级限压降维打击（使用 12V 动力源安全驱动 3V 电机，严格限制 25% PWM 占空比）。
* **自动散热 (Motor A)**：智能判断热超调与余温（待机 >35℃ 或加热超调 >0.5℃ 时），自动启动 12V 满血风扇排热。


* **丝滑 UI 异步渲染**：独立分配 FreeRTOS HMI 刷新任务，降频至 2.5Hz (400ms)，避免串口洪水效应导致屏幕触摸假死。

## 🔌 3. 硬件接线与引脚定义

**⚠️ 极其重要的电源规范：**
本项目存在 12V (动力强电) 与 5V/3.3V (逻辑弱电)。**全系统所有 GND 必须相连（共地）！** 否则控制信号将彻底失效并极易烧毁主控。TB6612 和 HX711 的逻辑供电 `VCC` **必须接主控的 3.3V**。

| 外设模块 | 功能说明 | ESP32-C3 引脚 | 备注与避坑指南 |
| --- | --- | --- | --- |
| **HX711** | DOUT (数据) | `GPIO_NUM_0` |  |
| **HX711** | SCK (时钟) | `GPIO_NUM_1` |  |
| **HMI 屏幕** | TX (发往屏幕) | `GPIO_NUM_21` | 接屏幕的 RX。勿用 UART0 (控制台占用) |
| **HMI 屏幕** | RX (来自屏幕) | `GPIO_NUM_20` | 接屏幕的 TX。 |
| **SSR 继电器** | PWM 控制极 | `GPIO_NUM_4` | 输出高低电平控制继电器通断 |
| **TB6612** | STBY (待机唤醒) | `GPIO_NUM_3` | 置高电平启动芯片 |
| **TB6612** | PWMA (风扇调速) | `GPIO_NUM_5` | LEDC 通道 0 |
| **TB6612** | AIN1 / AIN2 (风扇) | `GPIO_NUM_6` / `7` | 风扇方向控制 |
| **TB6612** | PWMB (搅拌调速) | `GPIO_NUM_10` | LEDC 通道 1 (宏定义最高限制 25%) |

## 🧠 5. 代码核心设计说明

1. **组件解耦架构**：`espnow_receiver` 不直接包含控制逻辑，而是暴露 `espnow_set_recv_cb()` 回调接口，由 `main.c` 统一接管数据路由，避免头文件循环依赖。
2. **硬件级电机断电**：针对 ESP32 在 0% PWM 占空比时存在的微秒级高电平毛刺，`motor_driver.c` 放弃使用 `ledc_set_duty(0)`，改用 `ledc_stop()` 与高阻态 `IN1=0, IN2=0`，实现物理级的电机急停，防止搅拌器失控微动。
3. **物理量纲统一 (SI)**：UI 传回的 CP 值 (如 420) 在底层严格换算为标准比热容单位 `J/(kg·℃)` (4200)，质量换算为 `kg`，确保前馈 PID 功率计算物理闭环。
4. **多任务时序保护**：
* `thermal_control_task`：0.1s 周期，处理严密的 PID 积分与硬件保护。
* `hmi_ui_update_task`：0.4s 周期，负责降低串口并发吞吐，保障 HMI 触摸侦测算力。



## 🛠️ 6. 二次开发与编译说明

### 6.1 开发环境

* **Framework**: ESP-IDF v5.x / v6.x
* **IDE**: VSCode + ESP-IDF Extension (或纯命令行终端)
* **CMake**: 组件化构建要求严格声明 `REQUIRES`。

### 6.2 编译与烧录

1. 清理损坏的缓存 (首次构建或增删文件后必须执行)：
```bash
idf.py fullclean

```


2. 编译项目：
```bash
idf.py build

```


3. 烧录并打开监视器：
```bash
idf.py -p COMx flash monitor

```


*(注：如果因为误用 IO18/IO19 导致 COM 口丢失，请按住开发板 `BOOT` 键再按 `RST` 键，进入硬件下载模式盲烧。)*

### 6.3 关键参数调整 (Tuning)

如需调整设备的硬件表现，直接修改 `main.c` 顶部的宏定义即可，无需深入组件内部：

* **`STIR_SPEED_PWM`** (默认 `25`)：控制 3V 搅拌电机在 12V 供电下的极限速度。
* **`WEIGHT_DEADZONE_G`** (默认 `0.5f`)：电子秤抗震动死区，如果工作台震动大，可适当上调至 `1.0f`。

### 6.4 ESP-NOW 重新配对指导

本项目的接收端（搅拌器主控）被动接收。如果你更换了发送端（温度采集板），你有两种方式应对：

1. **常规方式**：通过串口监视器读取搅拌器主控的真实 MAC 地址（启动日志已打印），并硬编码到发送端 C3 中。
2. **MAC Spoofing (伪装)**：如果发送端已被物理封胶无法修改代码，可在 `espnow_receiver.c` 的初始化流程中使用 `esp_wifi_set_mac()` 强制覆写主控板的底层 MAC 地址以迎合发送端。
